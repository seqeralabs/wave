Wave 1.33.0 was released on March 13, 2026.

## Mandatory steps

Wave 1.33.0 adds Server-Side Request Forgery (SSRF) protection to the `/validate-creds` endpoint,
which Seqera Platform calls when a user saves container registry credentials. The check is enabled
by default and rejects registry hosts that resolve to an internal address:

- `localhost` and `localhost.localdomain`, `0.0.0.0`, `::1`
- loopback, link-local and private (RFC 1918) addresses, and IPv6 unique local addresses
- the cloud metadata service addresses `169.254.169.254`, `169.254.170.2` and `fd00:ec2::254`
- any host that cannot be resolved

If your users register credentials for a container registry on a private network — an on-premises
registry, or one reachable only inside the VPC — saving those credentials fails with
`Invalid registry hostname` after this upgrade. Existing credentials are unaffected: only
validation of new or edited credentials goes through this check.

To keep registering credentials for internal registries, disable the check:

```yaml
wave:
  security:
    ssrf-protection:
      enabled: false
```

From [1.41.0](./1-41-0.md) onwards this setting defaults to `false`, so the override is only
required on releases 1.33.0 to 1.40.4.
